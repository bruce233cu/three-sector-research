# 三大赛道高赔率研究系统 — UI/UX V2

## 目标
把当前“后台管理页”升级为“高频研究终端”：少读、多扫、一眼判断下一步动作。保留深色金融终端风格，不做花哨视觉。

## 1. 全局视觉规范
- PC 正文：15px，line-height 1.55；不得低于 14px。
- 表格正文：14px；表头 13px/600；表格行高 48px（舒适）/40px（紧凑）。
- 页面标题：26px/700；模块标题：18px/650；辅助文字：13px。
- 关键数字：24–32px/700；必须明显高于正文。
- 内容区最大宽度：1600px；在大屏上充分利用横向空间。
- 左侧导航：220px 左右；当前模块高亮明显。
- 卡片圆角 8px；减少大面积空卡片和无意义留白。
- 同一屏最多 3 个视觉层级：主结论 > 操作/关键数字 > 辅助信息。
- 增加“舒适 / 紧凑”密度切换并记住用户选择。

## 2. 总览 Dashboard
第一屏只回答“今天发生了什么、我要处理什么”。

顶部 5 个 KPI：
1. 今日原始线索
2. 有效信号
3. 新增入池
4. 赔率变化
5. 待验证

第二层：机器人 / 商业航天 / AI 三张赛道状态卡。每张只显示：当前状态、今日新增信号、入池公司、待验证数量、最新关键变化。

第三层：“今日优先处理”队列，按优先级展示需要研究、核算、验证的事项。

第四层才展示最新信号和最新公司变化。

## 3. 前置信号
默认使用紧凑数据表，不再使用高纵向占用的长行卡片。

固定核心列：时间｜赛道｜变化摘要｜类型｜评分｜验证状态｜动作。
- “变化摘要”最多两行，详情进入抽屉/二级页。
- 支持：赛道、类型、评分、状态、日期筛选；全文搜索；排序；分页。
- 默认 25 条/页，可切 50/100。
- 评分 >= 8、待验证、高优先级用视觉强调，但不要大面积彩色背景。
- 点击一行打开信号详情，展示原始来源、变化、产业链传导、影响公司、验证项、历史更新。

## 4. 机会池
核心目标：一眼看出“为什么在池里、现在赔率多少、下一步验证什么”。

核心列：公司｜赛道｜产业链位置｜入池原因摘要｜当前市值｜中性目标市值｜当前赔率｜研究状态｜下一验证项。
支持按赔率、置信度、赛道、状态排序筛选。

## 5. 公司研究列表
列表只承担“找公司和比较”，不堆研究正文。
核心列：公司｜赛道｜产业链位置｜核心逻辑｜当前市值｜当前赔率｜置信度｜状态｜最新更新。
真实分页；数据不足一页时不得显示不存在的页码。

## 6. 公司详情页（核心）
### 顶部 Hero
公司名 / 股票代码 / 赛道 / 产业链位置 / 研究状态。
大数字展示：当前市值｜中性目标市值｜当前赔率｜综合置信度。
紧接一行“一句话核心逻辑”。

### 第一屏：决策摘要
左 2/3：为什么入池、核心产品、客户/订单、竞争优势。
右 1/3：3 个核心证据 + 3 个待验证问题。
用户不滚动即可理解当前研究结论。

### 证据链
按：原始信号 → 发生变化 → 产业链传导 → 对公司影响 → 证据来源 → 验证状态。
每条证据必须可追溯来源和日期。

### 利润核算
年度列：2026E / 2027E / 2028E；情景：悲观 / 中性 / 乐观。
展示：销量 × ASP → 收入 → 毛利率 → 费用率/净利率 → 增量净利润 → 总净利润。
默认展示中性，允许展开悲观/乐观。

### 估值与赔率
展示：当前市值 → 目标净利润 → 估值方法/倍数 → 目标市值 → 上行倍数。
赔率必须显示计算公式和关键假设，不只显示结果。

### 动态验证
分为：已验证 / 待验证 / 被证伪。每项带更新时间和证据。

### 研究时间轴
记录首次发现、入池、关键订单、利润假设调整、估值调整、赔率变化、证伪/退出等。
目标是能回答“当时为什么判断、后来为什么改变”。

## 7. 净利润核算页
不是简单结果表，而是模型工作台。
顶部支持公司/赛道/年度筛选。
主表展示三情景关键参数和净利润结果；点击进入完整计算明细。
显著标识“缺参数”“待验证参数”“数据过期”。

## 8. 赔率池
默认按公司平铺，不做推荐/排名结论；用户可自主按赔率、赛道、市值、研究状态排序。
核心列：公司｜赛道｜当前市值｜目标净利润｜估值方法｜目标市值｜上行倍数｜关键假设｜更新时间。
必须保留历史赔率变化，不能覆盖旧值。

## 9. 产业链地图
默认先展示结构，不追求复杂动画。
赛道 → 环节 → 产品/技术 → 公司。
点击节点进入相关公司/信号；支持只看机器人/商业航天/AI。

## 10. 历史日报
按日期分页；每日日报固定摘要：原始线索数、有效信号数、新增入池、赔率变化、待验证。
支持按赛道、日期范围检索；日报中的公司/信号可以跳转到对应详情。

## 11. 响应与性能验收
必须使用真实测试数据验收，不以静态 UI 为完成：
- 50 条信号：筛选/搜索/排序/25-50-100 分页正常。
- 30 家公司：真实分页、公司详情跳转正常。
- 每家公司至少 3 年 × 3 情景利润数据。
- 每家公司至少 3 个估值快照，验证历史变化。
- 2000 条信号场景下页面不能一次性全量渲染。
- loading / empty / error 三种状态必须存在。

## 12. 完成定义
页面存在 ≠ 完成。
只有以下四层全部通过才算完成：
1. UI 结构通过
2. Supabase 真实数据读取通过
3. 新增/修改数据写回通过
4. 测试数据量下筛选、分页、详情、历史变化真实跑通
