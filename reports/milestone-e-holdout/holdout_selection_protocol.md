# Holdout Selection Protocol

## 1. 角色隔离

| 角色 | 可见信息 | 禁止事项 |
|---|---|---|
| pool builder | 行业历史、公开复盘、独立价格/成交统计 | V4-A状态、规则组、counter、逐例输出 |
| label reviewer A/B | 候选episode和独立证据 | 相互评分、V4-A输出、开发集失败归因细节 |
| adjudicator | 两份已封存意见及证据 | 为满足配额强行改标签 |
| data qualifier | 固定窗口、数据版本、PIT/coverage | 修改标签或事件窗 |
| contamination auditor | Development registry、历史报告、候选元数据 | 运行候选规则 |
| executor | 已冻结casebook与manifest | 改样本、标签、窗口或成功标准 |

同一人可承担工程操作，但每一步必须生成带时间戳、输入checksum和结论的独立审计记录；标签意见必须在规则输出不可见时封存。

## 2. 候选池来源

优先顺序：

1. 开发集之后且处于认证数据终点前、从未用于诊断的历史区间；
2. 认证范围内更早、但从未进入任何报告、casebook或校准讨论的独立episode；
3. 若认证范围无法提供合格的10/10/5，则停止冻结，先扩展并重认证Warmup Data Version，不以低质量或污染样本补足。

允许使用行业指数、逐日成员的独立统计、权威媒体/券商/交易所公开复盘作为候选发现来源。禁止以V4-A或BASELINE的状态、候选日、置信度、规则通过矩阵发现case。

## 3. 选样步骤

1. 先登记`episode_id`、行业、催化簇和粗略时间范围，不设标签。
2. 根据标签合同形成独立证据包；每条证据记录发布日期和是否晚于事件。
3. A/B复核者分别给出`positive/negative/ambiguous/reject`、事件窗及置信度。
4. 标签一致且窗口边界差异不超过2个交易日，可合并；否则第三人裁决或拒绝。
5. 运行污染审计；任何同episode、报告引用或结果窥视均拒绝。
6. 在不看规则结果的前提下按预注册分层配额抽取：标签、市场风格、行业、形态、年份/市场环境。
7. 执行逐例Warmup资格；失败者只可在冻结前由同一分层的预备case替换，且替换记录永久保留。
8. 生成casebook及manifest checksum并冻结。

## 4. 分层配额

- 正例10个：至少覆盖4个行业风格、4种主线形态、3种市场环境；单一行业最多3个、单一宏观/政策催化簇最多2个。
- 负例10个：八类假主线至少覆盖6类；单一行业最多3个、单一催化簇最多2个。
- 模糊例5个：至少覆盖二波、快速轮动、结构性行情三类中的两类。
- 同一`episode_id`只能出现一次；相关行业共享同一跨行业episode时只能保留一个代表case。

## 5. 冻结与候补

冻结前可保留不超过每类30%的已审查候补，但候补不进入已冻结casebook。casebook冻结后，即使资格在执行阶段失败，也不得用候补替换；最终只能判`HOLDOUT INCONCLUSIVE`并消费该casebook。

## 6. 明确禁止

- 用“V4-A正好命中/没命中”决定保留、标签或窗口；
- 用P10、N02、N04、N08相似性作为入选理由；
- 将同一行情切成多个case；
- 看到结果后延长事件窗以制造命中；
- 删除难例、NULL例或误报例；
- 用当前成员替代历史成员，或用未来资料解释当时标签。
