> **状态：SPECIFICATION_ONLY / NOT_EXECUTED**  
> **资格：CALIBRATION_ONLY / DIAGNOSTIC_ONLY；G5 = FAIL**  
> 本规格只冻结三个介于 V1-B 与 V1-C 之间的平行结构候选。它不修改正式规则、阈值、状态机或生产配置，也不授权执行实验或 Holdout。

## 1. Executive Summary

上一轮已经给出清晰边界：

- V1-B 保住了负例护栏，但只把 P10 从事件后第37个交易日提前到事件后第4日；全窗口召回仍为6/10，改善只来自一个 episode。
- V1-C 把事件期召回提高到9/10、全窗口提高到10/10，却新增 N08 误确认，并把负例 S2 暴露从11日推高到19日。
- 因此问题不是“B应不应该存在”，而是：**B不足时，系统缺少一条同时要求绝对广度质量与多日持续性的补偿路径。**

本规格冻结三个候选：

1. **V1-B2：广度合格的加权证据**——最小结构修补，先验证现有绝对广度门槛能否阻断低基数脉冲。
2. **V1-B3：B非对称双路径**——B满足时确认较快；B不满足时必须付出更强支持证据和更长时间成本。
3. **V1-B4：三日分层待确认**——将弱B案例放入隔离实验态，只有后续两日继续成立才确认。

三个候选互相独立、都只与 BASELINE 比较；任何失败候选不得成为另一个候选的父版本。执行阶段禁止追加候选或调整门槛。

## 3. 为什么 V1-B 与 V1-C 都失败

### 3.1 V1-B：时间成本足够，但补偿条件过窄

V1-B 只允许 `A + C + D + Enhancer` 在 B=False 时连续3个有效交易日。它正确恢复了 P10，且没有新增负例误确认；但它仍把以下情形全部排除：

- B已经恢复，但 C 或 Enhancer 短暂缺一项；
- A、D和中期广度质量持续很强，但支持证据在 C/Enhancer 之间轮换；
- C 为 NULL、却已有 B 与 Enhancer 两份真实支持证据的情形。

结果是全窗口召回仍为6/10，无法满足多case、多episode改善要求。

### 3.2 V1-C：支持票放宽，却没有质量底座

V1-C 使用 `A AND D AND 至少2项(B/C/Enhancer)` 连续2日。它不再要求 B，也不区分“高绝对广度下的扩张”和“极低广度基数上的相对改善”。N08 正是在绝对广度很低时，通过了相对扩张类 D 证据并被确认。

因此 V1-C 的问题不是“2-of-3”本身，而是：

1. 缺少绝对广度安全底座；
2. B缺失与B满足使用相同的确认成本；
3. 两日条件不足以过滤快速衰减的防御脉冲。

### 3.3 真正的结构差异

V1-B 把 **连续3日** 当作唯一补偿；V1-C 把 **支持票数** 当作唯一补偿。中间结构应同时具备：

- 沿用正式 profile 已存在的绝对广度门槛 `above_ma20 >= 0.60`，不发明新阈值；
- B仍是重要证据，B=False 必须承担更长确认时间；
- 支持证据按日重新验证，不能靠一次爆发永久获得资格；
- NULL不计票、不默认通过；Freeze暂停但不推进计数。

| 维度 | P10（V1-B恢复） | N08（V1-C误放） | 结构含义 |
| --- | --- | --- | --- |
| A相对强度 | 5/7–5/12连续4日A=True；rs10约0.013→0.087 | 12/30–12/31连续2日A=True；rs10约0.024→0.027，随后1/2 A=False | P10持续增强；N08快速失效 |

| D与绝对广度 | D连续为True；above_ma20约0.917–0.955，above_ma60约0.654–0.877 | D可为True，但above_ma20仅约0.114–0.143，above_ma60约0.171 | N08是低基数相对扩张，不是高覆盖主线 |
| 成交持续性 | turnover_intensity约1.88→2.89，连续抬升 | 约1.31→1.47，随后回落 | P10的资金共振更强、更持续 |
| 多日持续 | A/C/D/Enhancer连续4日同时成立 | 完整组合仅连续2日，下一日A/D失效 | 多日验证可以过滤N08型短脉冲 |
| S1路径 | 连续S1，V1-B在事件后第4日确认 | 12/25短进S1、12/26回S0，12/27再入S1 | N08确认前已有明显候选反复 |
| 结果解释 | B很弱，但其他证据形成持续、高覆盖共振 | B短暂恢复，但底层广度仍极低 | 应补偿“持续共振”，不能补偿“低基数反弹” |

**关键结论：** P10与N08的主差异不在B失败距离，而在绝对广度水平、证据持续时间、成交强度及确认前状态稳定性。候选规则不得把case身份写入逻辑，只能使用这些同期可得结构证据。

### 5.2 共同安全底座

所有新增补偿路径都必须满足：

1. 当前状态为S1，且当日非Freeze；
2. A=True、D=True；
3. `above_ma20 >= 0.60`。该数值直接复用当前正式profile的`confirm.above_ma20_min`，不是新阈值；
4. `above_ma20`为NULL时补偿路径结果为NULL，不得默认通过；
5. 支持票中的NULL不计为TRUE；如果无法满足最低真实票数，则不推进确认计数；
6. 标准 `A AND B AND C AND D AND Enhancer` 连续2日路径完整保留。

绝对广度底座是本轮唯一新增资格层；禁止临时再添加above_ma60、turnover或rs10数值门槛。

## 7. 候选二：V1-B3 — ASYMMETRIC B ROLE

标准路径保持不变，补偿路径分成两个互斥分支：

- **B-present分支：** 共同安全底座 + B=True +（C或Enhancer至少1项TRUE），连续2个有效交易日；
- **B-waived分支：** 共同安全底座 + B=False + C=True + Enhancer=True，连续3个有效交易日；
- B=NULL时不得进入任何补偿分支；两个分支的连续计数独立，不能把一天B-present和一天B-waived拼成连续满足。

| 项目 | 冻结说明 |
| --- | --- |
| B角色 | 仍决定确认成本：有B需2日；无B需完整C+Enhancer并持续3日 |
| A/D角色 | 每个合格日均为硬核心；D另受above_ma20正式门槛约束 |
| Persistence角色 | 用不对称时间成本补偿B缺失，不降低B原子阈值 |
| 二次确认 | 是；B-present第2日、B-waived第3日确认 |
| 预期改善 | 同时覆盖“B已恢复但一个辅助项波动”和“B未恢复但其他证据持续”的两类真主线 |
| 主要副作用 | 两条计数路径提高实现复杂度；B边界来回切换可能导致迟迟不确认 |
| 最可能新增正例 | P10可能走B-waived；P01/P03/P09可能走B-present，具体以执行结果为准 |
| 最可能新增负例 | 高绝对广度且B短暂满足的轮动；N08仍应被绝对广度底座阻断 |
| 过拟合风险 | 中低；结构体现“证据弱则付出更多时间”，不依赖具体case或行业 |

## 8. 候选三：V1-B4 — THREE-DAY STAGED CONFIRMATION

补偿路径只在隔离实验中模拟`S1-confirm-pending`，不改变正式状态枚举：

1. **Pending Day 1：** 共同安全底座成立，B/C/Enhancer至少2项TRUE；
2. **Validation Day 2–3：** 后续两个非Freeze交易日继续满足共同安全底座，且每天B/C/Enhancer至少2项TRUE；
3. 三日内必须满足以下之一：B至少1日为TRUE；或B三日均为FALSE且C与Enhancer三日均为TRUE；
4. 任一日出现核心条件明确FALSE则立即取消pending；NULL不算通过、不推进天数；Freeze暂停；pending在5个非Freeze交易日内未完成则自动失效；
5. 第3个合格日才允许实验性S1→S2。

| 项目 | 冻结说明 |
| --- | --- |
| B角色 | 可以迟到，也可以由C+Enhancer三日完整替代，但不能无成本缺席 |
| A/D角色 | 三个验证日必须持续；D另受绝对广度底座约束 |
| Persistence角色 | 显式验证“进入观察→继续成立→最终确认” |
| 二次确认 | 是，且为三个合格日的分层确认 |
| 预期改善 | 过滤两日脉冲，同时给慢一拍的B或持续的非B证据第二次机会 |
| 主要副作用 | 最可能增加确认滞后；快速启动主线可能到第3日才确认 |
| 最可能新增正例 | 持续至少3日的P10/P01/P09型结构；两日即结束的case可能仍漏报 |
| 最可能新增负例 | 高广度且持续3日的假突破；N08因广度底座与后续核心失效应被阻断 |
| 过拟合风险 | 中等；结构清晰但状态更复杂，必须审计pending超时和Freeze行为 |

## 11. Guardrails 与 Stop Rule

### 11.1 单候选直接失败

任一情况成立即标记该候选`FAIL`：

- 负例新误确认>1，或负例S2暴露>11日；
- 原有5个正例事件期命中丢失任意1例；
- 全窗口召回<7/10，或改善只来自一个case/episode；
- matched-lag、Churn或负例S1滞留突破第10节门槛；
- NULL默认通过、窗口缩短、Freeze推进计数、非法状态转移或确定性失败；
- 改善主要来自直接warmup敏感case，且剔除敏感case后不再有多case改善；
- 实现使用case_id、行业名、事件日期、标签或未来信息。

### 11.2 执行级停止

1. BASELINE与上一轮逐case、逐日checksum不一致：标记`HARNESS_FAIL`，三个候选全部不执行。
2. 某候选失败：记录失败原因，继续下一个独立候选；不得修补失败候选，也不得把它叠加到后续候选。
3. 若发现共同输入、日历、profile、casebook或warmup资格漂移：停止剩余候选并标记`BLOCKED_BY_DATA_OR_BASELINE_DRIFT`。
4. 三个候选均失败：结论只能是`NO CANDIDATE PASSED`。
5. 至少一个候选通过：结论只能是`CALIBRATION CANDIDATE FOUND — HOLDOUT REQUIRED`，停止，不自动运行Holdout。

### 11.3 多候选同时通过时的固定选择顺序

不使用综合分。依次比较：

1. 更少的负例新确认；
2. 更少的负例S2暴露；
3. 更高的事件期召回，再比较全窗口召回；
4. 更好的matched-lag；
5. 更低的Churn和负例S1滞留；
6. 若仍完全并列，按更小变更面优先：`V1-B2 → V1-B3 → V1-B4`。
